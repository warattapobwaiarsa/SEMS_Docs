เอกสารนี้รวบรวมเฉพาะเรื่องที่ยังไม่มีคำตอบสุดท้าย หรือมีเพียงข้อเสนอชั่วคราวในเอกสารของโครงการ เพื่อใช้ถามอาจารย์ เจ้าหน้าที่งานทุน ผู้ดูแลข้อมูล และหน่วยงานที่เกี่ยวข้องก่อนยืนยัน Requirement Baseline และเริ่มพัฒนาระบบจริง

> **วิธีใช้:** ให้ถามตามลำดับความสำคัญ โดยบันทึกคำตอบ ผู้ให้คำตอบ วันที่ และหลักฐาน เช่น อีเมล บันทึกประชุม หรือเอกสารที่ได้รับอนุมัติ

### Q-001 ข้อมูลตัวอย่างใน Repository เป็นข้อมูลจำลองทั้งหมดหรือไม่?

- ผู้ที่ควรถาม: เจ้าหน้าที่งานทุน / เจ้าของข้อมูล / อาจารย์ที่ปรึกษา
- คำตอบที่ต้องการ:
  - [x] เป็นข้อมูลจำลองทั้งหมด
  - [ ] มีข้อมูลจริงบางส่วน
  - [ ] ยังตรวจสอบไม่ได้
- หากมีข้อมูลจริง: ต้องกำหนดว่าจะลบ ปกปิด หรือเปลี่ยน Repository เป็น Private

### Q-003 ระหว่างที่ยังยืนยันข้อมูลตัวอย่างไม่ได้ ควรเปลี่ยน Repository เป็น Private ชั่วคราวหรือไม่?

- ผู้ที่ควรถาม: อาจารย์ที่ปรึกษา / เจ้าของข้อมูล
- ข้อเสนอเริ่มต้นของทีม: เปลี่ยนเป็น Private จนกว่าจะยืนยันว่าข้อมูลทั้งหมดเป็นข้อมูลจำลองหรือผ่านการปกปิดแล้ว
- มติ/คำตอบ: ข้อมูลใน Repository คือข้อมูลตัวอย่างทั้งหมด

### Q-004 ข้อมูลแต่ละประเภทต้องเก็บไว้นานเท่าไร?

- ประวัติการนำเข้า

- ไฟล์รายงานที่ส่งออก
- ไฟล์สำรองข้อมูล

- ผู้ที่ควรถาม: เจ้าของข้อมูล / งานทุน / ผู้ดูแลระบบ

โปรดแบ่งข้อมูลเป็น 3 กลุ่ม:

1. **ต้องมีตอน Import**
2. **ยังว่างได้ตอน Import แต่ต้องครบก่อนเปิดให้ประเมิน**

# 10. เรื่องที่มีข้อสรุปแล้วและไม่จำเป็นต้องถามซ้ำ

จาก Proposal และ Requirement Decision Register มีข้อสรุปหลักแล้วดังนี้:

1. ผู้สมัครหนึ่งคนมีผู้ประเมินอย่างน้อย 2 คนและไม่เกิน 3 คนต่อรอบทุน
2. การจำกัดไม่เกิน 3 คนให้นับ Evaluation ที่ยังไม่ถูกยกเลิกทั้ง Draft และ Submitted
3. อาจารย์คนเดิมประเมินผู้สมัครคนเดิมซ้ำในรอบเดียวกันไม่ได้
4. ใช้เฉพาะผลสถานะ Submitted ในการคำนวณ
5. เมื่อ Submitted ครบ 2 คนแล้ว ผู้ประเมินคนที่ 3 ยังประเมินเพิ่มได้ก่อนปิดรอบ
6. เมื่อคนที่ 3 Submit ระบบต้องคำนวณผลสรุปใหม่
7. หากปิดรอบแล้วมี Submitted น้อยกว่า 2 คน ผู้สมัครเป็น `Closed Incomplete`
8. ผู้สมัครสถานะ `Closed Incomplete` ไม่มีคะแนนสรุปสุดท้าย
9. ระบบรองรับรอบทุน `Draft → Open → Closed → Archived`
10. Evaluator แก้ไขและ Submit ได้เฉพาะ Evaluation ของตนเอง
