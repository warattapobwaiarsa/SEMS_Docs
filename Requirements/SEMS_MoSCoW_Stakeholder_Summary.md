## 3. วัตถุประสงค์

เอกสารนี้สรุปขอบเขตของระบบ SEMS ให้ตรวจสอบได้รวดเร็ว และใช้ประกอบการสนทนากับอาจารย์ ลูกค้า หรือผู้มีส่วนได้ส่วนเสีย โดยเน้นสิ่งที่ผู้ใช้ทำได้ ผลกระทบหากไม่มีความสามารถนั้น และเหตุผลที่บางรายการเลื่อนได้หรือไม่อยู่ในโครงการ

เอกสารนี้ไม่แทนเอกสารข้อกำหนดฉบับละเอียด ไม่เพิ่มหรือลดขอบเขต และไม่เปลี่ยนกลุ่ม MoSCoW จาก [เอกสาร MoSCoW ฉบับละเอียด](./SEMS_MoSCoW_Feature_Prioritization.md) ซึ่งเป็นแหล่งข้อมูลหลัก

## 4. ระบบ SEMS ทำอะไร

SEMS ช่วยจัดการกระบวนการประเมินทุนตั้งแต่ผู้ดูแลระบบนำเข้าข้อมูลผู้สมัคร จัดเก็บข้อมูลและเอกสารประกอบ เตรียมรอบทุนและเกณฑ์การประเมิน ไปจนถึงผู้ประเมินเลือกผู้สมัคร ให้คะแนน บันทึกแบบประเมิน และยืนยันส่งผล ระบบจะรวมผลจากผู้ประเมินที่ไม่ซ้ำกัน 2–3 คนตามกติกาที่กำหนด

ผู้ดูแลระบบสามารถติดตามความครบถ้วน ปิดรอบ และส่งออกรายงานเพื่อใช้ในกระบวนการของคณะได้ แต่ SEMS ไม่ครอบคลุมการรับสมัครทุนจากนักศึกษา การอนุมัติทุนขั้นสุดท้าย การประกาศผลโดยตรงแก่นักศึกษา หรือการจ่ายเงินทุน

## 5. วิธีอ่าน MoSCoW

| กลุ่ม | ความหมายแบบเข้าใจง่าย |
| :--- | :--- |
| **Must have** | ไม่มีแล้วระบบไม่สามารถทำงานหลักได้ หรือไม่ปลอดภัยพอที่จะใช้งานจริง |
| **Should have** | สำคัญและควรมี แต่สามารถเลื่อนไปพัฒนาในภายหลังได้ |
| **Could have** | มีแล้วช่วยให้ใช้งานสะดวกขึ้น แต่ไม่มีระบบก็ยังทำงานได้ |
| **Won't have** | ตกลงว่าไม่ทำในโครงการหรือรุ่นนี้ |

## 6. สรุปความสามารถตาม MoSCoW

### 6.1 Must have

| ความสามารถ | กลุ่ม | เหตุผลที่จัดไว้กลุ่มนี้ |
| :--- | :---: | :--- |
| เข้าสู่ระบบ ออกจากระบบ และจำกัดสิทธิ์ผู้ใช้ | Must have | หากไม่มี ผู้ใช้จะเริ่มงานไม่ได้ หรืออาจเห็นและแก้ไขข้อมูลของผู้อื่น ทำให้ระบบไม่ปลอดภัยพอสำหรับใช้งานจริง |
| จัดการบัญชีและบทบาทผู้ใช้งาน | Must have | ผู้ดูแลระบบต้องเตรียมบัญชี กำหนดบทบาท และระงับสิทธิ์ได้ มิฉะนั้นจะควบคุมผู้ที่เข้าถึงข้อมูลผู้สมัครและผลประเมินไม่ได้ |
| สร้าง เตรียม และเปิดรอบทุน | Must have | ข้อมูลผู้สมัคร เกณฑ์ และผลประเมินต้องแยกตามรอบ หากไม่มีรอบทุน กระบวนการประเมินจะเริ่มไม่ได้ |
| นำเข้าและตรวจสอบข้อมูลผู้สมัคร | Must have | เป็นช่องทางหลักในการนำข้อมูลเข้าสู่ระบบ และต้องตรวจความครบถ้วนหรือข้อมูลซ้ำก่อนใช้ประเมิน |
| จัดการข้อมูลและเอกสารผู้สมัคร | Must have | ผู้ประเมินต้องเห็นข้อมูลและเอกสารที่ครบถ้วนตามสิทธิ์เพื่อใช้ประกอบการให้คะแนน |
| กำหนด ตรวจสอบ และเปิดใช้เกณฑ์การประเมิน | Must have | หากไม่มีเกณฑ์ที่ชัดเจนและคงที่ ผู้ประเมินจะให้คะแนนไม่ได้และผลจากแต่ละช่วงเวลาอาจเทียบกันไม่ได้ |
| ค้นหาและเลือกผู้สมัครเพื่อสร้างแบบประเมิน | Must have | ผู้ประเมินต้องเลือกผู้สมัครในรอบที่เปิด และระบบต้องป้องกันผู้ประเมินซ้ำหรือเกิน 3 คน |
| กรอก บันทึก ตรวจทาน และส่งผลประเมิน | Must have | เป็นขั้นตอนหลักในการสร้างผลประเมิน โดยผู้ประเมินต้องบันทึกงานค้าง ตรวจคะแนน และยืนยันผลก่อนนำไปคำนวณ |
| คำนวณและสรุปคะแนนจากผู้ประเมิน | Must have | ระบบต้องรวมเฉพาะผลที่ยืนยันแล้วจากผู้ประเมินไม่ซ้ำกัน และคำนวณใหม่เมื่อมีผู้ประเมินคนที่ 3 |
| ตรวจความครบถ้วนและปิดรอบ | Must have | ผู้ดูแลระบบต้องเห็นรายการที่ยังไม่ครบก่อนปิดรอบ และกำหนดสถานะของผู้สมัครที่ผลยังไม่ครบอย่างชัดเจน |
| ติดตามสถานะและส่งออกรายงานอย่างเหมาะสมกับสิทธิ์ | Must have | ผู้ดูแลระบบต้องติดตามภาพรวมและนำผลไปใช้ต่อได้ โดยรายงานต้องตรงกับผลสรุปและไม่เปิดเผยข้อมูลส่วนบุคคลเกินสิทธิ์ |

### 6.2 Should have

| ความสามารถ | กลุ่ม | เหตุผลที่จัดไว้กลุ่มนี้ |
| :--- | :---: | :--- |
| เก็บรอบที่เสร็จแล้วและเปิดรอบที่ปิดในกรณีพิเศษ | Should have | รอบปกติยังปิดและส่งออกรายงานได้โดยไม่มีความสามารถนี้ แต่ควรมีเพื่อเก็บรอบเดิมแบบอ่านอย่างเดียวและรองรับข้อยกเว้นที่ได้รับอนุมัติ |
| แก้ไขข้อมูลและรายการมาตรฐานอย่างควบคุม | Should have | กระบวนการปกติทำงานได้เมื่อข้อมูลถูกต้องตั้งแต่แรก แต่ควรมีวิธีแก้ข้อผิดพลาดโดยเก็บเหตุผลและข้อมูลก่อน–หลัง |
| ยกเลิกแบบประเมินฉบับร่าง | Should have | ช่วยคืนช่องให้ผู้ประเมินคนอื่นเมื่อเลือกรายการผิด แต่ไม่จำเป็นต่อการประเมินในกรณีปกติ |
| เปิดผลประเมินที่ส่งแล้วให้แก้ไข | Should have | ใช้แก้ข้อผิดพลาดหลังส่งผลโดยต้องขออนุมัติและเก็บผลเดิม กระบวนการปกติไม่ต้องใช้ขั้นตอนนี้ |
| ดูรายละเอียดจากแดชบอร์ดและใช้รายงานหลายระดับ | Should have | ภาพรวมและรายงานพื้นฐานยังทำงานได้ แต่รายละเอียดเพิ่มเติมช่วยตรวจงานระหว่างดำเนินการและรองรับผู้รับรายงานหลายกลุ่ม |
| ดูและค้นหาประวัติการดำเนินงาน | Should have | การเก็บประวัติยังจำเป็นตั้งแต่แรก แต่หน้าสำหรับค้นหาประวัติสามารถเลื่อนได้โดยไม่หยุดกระบวนการประเมินปกติ |

### 6.3 Could have

| ความสามารถ | กลุ่ม | เหตุผลที่จัดไว้กลุ่มนี้ |
| :--- | :---: | :--- |
| เครื่องมือช่วยลดขั้นตอนซ้ำในการใช้งาน | Could have | การออกจากทุกบริการของมหาวิทยาลัย การคัดลอกเกณฑ์เดิม และการบันทึกคะแนนอัตโนมัติช่วยประหยัดเวลา แต่มีวิธีพื้นฐานรองรับอยู่แล้ว |
| เครื่องมือช่วยค้นหาและจดบันทึกสำหรับผู้ดูแลระบบ | Could have | หมายเหตุภายในและการค้นหาขั้นสูงช่วยให้ทำงานสะดวกขึ้น แต่ข้อมูลหลักและการค้นหาพื้นฐานเพียงพอต่อกระบวนการหลัก |
| รูปแบบและการจัดชุดไฟล์รายงานเพิ่มเติม | Could have | รายงาน Excel/CSV แบบพื้นฐานส่งมอบข้อมูลได้ครบ ส่วนไฟล์ PDF แม่แบบเฉพาะ และการรวมไฟล์เป็นชุดเป็นความสะดวกเพิ่มเติม |
| เครื่องมือเสริมสำหรับติดตามงานและตรวจสอบรายละเอียด | Could have | การแจ้งเตือนและหน้าประวัติแบบละเอียดช่วยลดเวลาติดตาม แต่ผู้ใช้ยังดูสถานะและค้นหาประวัติแบบพื้นฐานได้ |

### 6.4 Won't have

| ความสามารถ | กลุ่ม | เหตุผลที่จัดไว้กลุ่มนี้ |
| :--- | :---: | :--- |
| บริการสมัครทุนและประกาศผลสำหรับนักศึกษาโดยตรง | Won't have | SEMS เริ่มทำงานจากข้อมูลที่เจ้าหน้าที่นำเข้า และผู้สมัครไม่ใช่ผู้ใช้ระบบในโครงการนี้ |
| การอนุมัติทุนขั้นสุดท้ายและการจ่ายเงิน | Won't have | SEMS จัดทำคะแนนและรายงานประกอบการตัดสินใจ แต่ไม่แทนอำนาจอนุมัติหรือระบบการเงิน |
| เชื่อมแทนระบบข้อมูลกลางหรือใช้เลขประจำตัวประชาชน | Won't have | รุ่นนี้ใช้การนำเข้าจากไฟล์ ไม่แทนฐานข้อมูลกลาง และไม่รองรับเลขประจำตัวประชาชนโดยไม่มีการอนุมัติแยก |
| จัดการรหัสผ่านบัญชีมหาวิทยาลัย | Won't have | รหัสผ่านอยู่ภายใต้ระบบบัญชีมหาวิทยาลัยอยู่แล้ว การจัดการซ้ำใน SEMS ไม่อยู่ในขอบเขต |
| แอปพลิเคชันโทรศัพท์มือถือโดยเฉพาะ | Won't have | โครงการส่งมอบเป็นเว็บแอปพลิเคชัน ส่วนแอปสำหรับโทรศัพท์ต้องพัฒนาและตรวจสอบแยกต่างหาก |
| จัดการการมอบหมายล่วงหน้า นัดสัมภาษณ์ หรือไฟล์ Excel รุ่นเก่า | Won't have | กระบวนการที่ยืนยันให้ผู้ประเมินเลือกผู้สมัครเอง ไม่รวมการจัดประชุมออนไลน์ และรุ่นนี้รองรับไฟล์รูปแบบปัจจุบันที่กำหนดไว้แล้ว |

## 7. สิ่งที่อยู่นอกตารางความสามารถ

ความปลอดภัย การสำรองและกู้คืนข้อมูล การเก็บรักษาและลบข้อมูล ประสิทธิภาพ การตรวจสอบย้อนหลัง ความเข้ากันได้กับเว็บเบราว์เซอร์ การเข้าถึง และการบำรุงรักษาระบบยังมีความสำคัญ แต่เป็นมาตรการภายในหรือข้อกำหนดด้านคุณภาพ จึงเก็บรายละเอียดไว้ในหัวข้อ [ข้อกำหนดสนับสนุนและข้อกำหนดที่ไม่ใช่เชิงหน้าที่](./SEMS_MoSCoW_Feature_Prioritization.md#6-ข้อกำหนดสนับสนุนและข้อกำหนดที่ไม่ใช่เชิงหน้าที่) ของเอกสารฉบับละเอียด

| การเจาะดูรายละเอียดจากแดชบอร์ด | คงเป็น Should have | ภาพรวมเพียงพอต่อการติดตามหลัก แต่รายละเอียดช่วยลดเวลาค้นหาและตรวจปัญหา | ยืนยัน / ขอเปลี่ยนแปลง / ต้องหารือเพิ่มเติม |
| รูปแบบรายงานหลายระดับ | คงเป็น Should have โดยใช้รายงานพื้นฐานก่อน | รายงานพื้นฐานส่งมอบผลได้ ส่วนรายงานระหว่างดำเนินการและหลายระดับช่วยตอบผู้ใช้หลายกลุ่ม | ยืนยัน / ขอเปลี่ยนแปลง / ต้องหารือเพิ่มเติม |
| การยกเลิกแบบประเมินฉบับร่าง | คงเป็น Should have และไม่ลบประวัติ | ช่วยแก้กรณีผู้ประเมินเลือกรายการผิดและคืนช่องให้ผู้อื่น โดยไม่กระทบกระบวนการปกติ | ยืนยัน / ขอเปลี่ยนแปลง / ต้องหารือเพิ่มเติม |

## ภาคผนวก A: การเชื่อมโยงกับความสามารถฉบับละเอียด

ตารางนี้ครอบคลุมความสามารถทั้ง 64 รายการจากเอกสาร MoSCoW ฉบับละเอียด โดยแต่ละรายการปรากฏหนึ่งครั้งและอยู่ในกลุ่มเดิม ดูรหัสอ้างอิงเพิ่มเติมได้ที่ [หัวข้อการเชื่อมโยงและตรวจสอบย้อนกลับ](./SEMS_MoSCoW_Feature_Prioritization.md#8-การเชื่อมโยงและตรวจสอบย้อนกลับ)

| ความสามารถในฉบับสรุป | กลุ่ม | ความสามารถที่ครอบคลุมในเอกสารฉบับละเอียด |
| :--- | :---: | :--- |
| เข้าสู่ระบบ ออกจากระบบ และจำกัดสิทธิ์ผู้ใช้ | Must have | เข้าสู่ระบบด้วยบัญชี KKU ผ่าน OAuth/OIDC<br>ควบคุมสิทธิ์ด้วย RBAC ตามบทบาท รอบทุน และความเป็นเจ้าของข้อมูล<br>ออกจากระบบ SEMS และยกเลิกวาระการใช้งาน |
| จัดการบัญชีและบทบาทผู้ใช้งาน | Must have | ค้นหาและดูบัญชี SEMS<br>เตรียมบัญชีล่วงหน้า เชื่อมตัวตน KKU และกำหนดบทบาท<br>เปิดหรือปิดสิทธิ์บัญชี SEMS |
| สร้าง เตรียม และเปิดรอบทุน | Must have | สร้างรอบทุน<br>แก้ไข ตรวจความพร้อม และเปิดรอบทุน |
| นำเข้าและตรวจสอบข้อมูลผู้สมัคร | Must have | อัปโหลด `.xlsx`/`.csv` และจับคู่คอลัมน์<br>แสดงตัวอย่าง ปรับรูปแบบ และตรวจสอบข้อมูลก่อนนำเข้า<br>ยืนยันการนำเข้าแบบครบทั้งชุดและเก็บประวัติชุดข้อมูล<br>รองรับผู้สมัครหนึ่งคนสมัครหลายประเภททุนในรอบเดียว |
| จัดการข้อมูลและเอกสารผู้สมัคร | Must have | ดูและจัดการข้อมูลผู้สมัครกับประวัติทุน/กยศ. โดยใช้สำเนาข้อมูลของแต่ละรอบ<br>ตรวจข้อมูลบังคับก่อนเริ่มประเมิน<br>อัปโหลดเอกสารผู้สมัคร<br>แสดงตัวอย่างหรือดาวน์โหลดเอกสารตามสิทธิ์ |
| กำหนด ตรวจสอบ และเปิดใช้เกณฑ์การประเมิน | Must have | สร้างชุดเกณฑ์ คะแนน และช่องข้อมูลผลลัพธ์สำหรับรอบทุน<br>ตรวจสอบและเปิดใช้รุ่นเกณฑ์<br>ล็อกรุ่นเกณฑ์ที่ใช้งานและสร้างรุ่นใหม่ |
| ค้นหาและเลือกผู้สมัครเพื่อสร้างแบบประเมิน | Must have | ค้นหาผู้สมัครในรอบที่เปิด<br>เลือกผู้สมัครและสร้างแบบประเมินฉบับร่างไม่ซ้ำ สูงสุด 3 คน |
| กรอก บันทึก ตรวจทาน และส่งผลประเมิน | Must have | แสดงข้อมูลผู้สมัคร เอกสาร ประวัติ และเกณฑ์ในหน้าประเมิน<br>กรอกคะแนน ความคิดเห็น และคำแนะนำภายใต้การตรวจสอบความถูกต้อง<br>บันทึกด้วยตนเองและกลับมาแก้แบบประเมินฉบับร่าง<br>ตรวจทานคะแนน ความคิดเห็น ช่องข้อมูลผลลัพธ์ และยอดรวมก่อนส่ง<br>ยืนยันการส่งผลประเมินและล็อกผล |
| คำนวณและสรุปคะแนนจากผู้ประเมิน | Must have | คำนวณคะแนนรวมรายผู้ประเมินจากคะแนนที่บันทึกไว้ในชุดเกณฑ์<br>สร้างคะแนนสรุปเมื่อมีผลประเมินสถานะ `SUBMITTED` ครบ 2 คน<br>คำนวณใหม่เมื่อผู้ประเมินคนที่ 3 ส่งผลประเมิน |
| ตรวจความครบถ้วนและปิดรอบ | Must have | ตรวจความครบถ้วนและปิดรอบ<br>กำหนดผลขั้นสุดท้ายหรือสถานะ `CLOSED_INCOMPLETE` หลังปิดรอบ |
| ติดตามสถานะและส่งออกรายงานอย่างเหมาะสมกับสิทธิ์ | Must have | แดชบอร์ดภาพรวมจำนวนผลที่ส่งและสถานะผู้สมัคร<br>ส่งออก Excel/CSV ให้ตรงกับผลสรุปคะแนน<br>ส่งออกข้อมูลตามสิทธิ์โดยไม่รวม PII ที่จำกัดการเข้าถึง |
| เก็บรอบที่เสร็จแล้วและเปิดรอบที่ปิดในกรณีพิเศษ | Should have | เก็บรอบทุนเป็นแบบอ่านอย่างเดียว<br>เปิดรอบทุนที่ปิดแล้วในกรณีพิเศษ และเก็บสำเนาผลสุดท้ายที่ถูกแทนที่ |
| แก้ไขข้อมูลและรายการมาตรฐานอย่างควบคุม | Should have | การแก้ไขแบบควบคุมพร้อมเหตุผล ข้อมูลก่อนและหลังแก้ และบันทึกตรวจสอบ<br>จัดการรายการรหัสมาตรฐานแบบมีรุ่นและบันทึกตรวจสอบ |
| ยกเลิกแบบประเมินฉบับร่าง | Should have | ยกเลิกแบบประเมินฉบับร่างโดยไม่ลบข้อมูลและคืนโควตาผู้ประเมิน |
| เปิดผลประเมินที่ส่งแล้วให้แก้ไข | Should have | ขออนุมัติและเปิดผลประเมินที่ส่งแล้วให้แก้ไข พร้อมบันทึกรุ่น |
| ดูรายละเอียดจากแดชบอร์ดและใช้รายงานหลายระดับ | Should have | กรองและดูรายละเอียดรายการจากแดชบอร์ด<br>รูปแบบรายงานตามระดับข้อมูล รายงานระหว่างดำเนินการ และสำเนาผลสุดท้ายที่แก้ไขไม่ได้ |
| ดูและค้นหาประวัติการดำเนินงาน | Should have | ดูและค้นหาเหตุการณ์ในบันทึกการตรวจสอบย้อนหลัง |
| เครื่องมือช่วยลดขั้นตอนซ้ำในการใช้งาน | Could have | ออกจากระบบ KKU ทุกบริการ<br>คัดลอกเกณฑ์จากรอบเดิมเป็นฉบับร่าง<br>บันทึกอัตโนมัติระหว่างกรอกคะแนน |
| เครื่องมือช่วยค้นหาและจดบันทึกสำหรับผู้ดูแลระบบ | Could have | หมายเหตุภายในสำหรับผู้ดูแลระบบ<br>การค้นหาขั้นสูง |
| รูปแบบและการจัดชุดไฟล์รายงานเพิ่มเติม | Could have | รวมไฟล์ CSV เป็น ZIP<br>ส่งออก PDF ใช้แม่แบบกำหนดเอง และรูปแบบรายงานเสริม |
| เครื่องมือเสริมสำหรับติดตามงานและตรวจสอบรายละเอียด | Could have | หน้าดูบันทึกการตรวจสอบแบบละเอียดและการค้นหาขั้นสูง<br>การแจ้งเตือนภายในระบบ |
| บริการสมัครทุนและประกาศผลสำหรับนักศึกษาโดยตรง | Won't have | ระบบสมัครทุนออนไลน์สำหรับนักศึกษา<br>ให้ผู้สมัครเข้าสู่ SEMS โดยตรง<br>ประกาศผลทุนแก่ผู้สมัครโดยตรง |
| การอนุมัติทุนขั้นสุดท้ายและการจ่ายเงิน | Won't have | การอนุมัติทุนขั้นสุดท้ายระดับนโยบาย/คณะกรรมการ<br>โอนเงินทุนหรือจัดการทางการเงิน |
| เชื่อมแทนระบบข้อมูลกลางหรือใช้เลขประจำตัวประชาชน | Won't have | เชื่อมตรงหรือแทนฐานข้อมูลทะเบียน/ระบบทุนกลาง<br>รองรับ National ID ใน Release 1 |
| จัดการรหัสผ่านบัญชีมหาวิทยาลัย | Won't have | จัดการหรือจัดเก็บรหัสผ่าน KKU ใน SEMS |
| แอปพลิเคชันโทรศัพท์มือถือโดยเฉพาะ | Won't have | แอปพลิเคชันสำหรับโทรศัพท์มือถือโดยเฉพาะ |
| จัดการการมอบหมายล่วงหน้า นัดสัมภาษณ์ หรือไฟล์ Excel รุ่นเก่า | Won't have | มอบหมายผู้สมัครให้อาจารย์ล่วงหน้า<br>จัดคิว/ห้องสัมภาษณ์ Zoom หรือควบคุมประชุมออนไลน์<br>นำเข้าไฟล์ `.xls` รุ่นเก่า |

## 10. คำศัพท์ที่ควรรู้

| คำ | ความหมายแบบย่อ |
| :--- | :--- |
| รอบทุน | ช่วงการดำเนินงานทุนหนึ่งรอบที่มีผู้สมัคร เกณฑ์ และผลประเมินของตนเอง |
| ผู้ดูแลระบบ | เจ้าหน้าที่งานทุนที่จัดการข้อมูล รอบทุน เกณฑ์ สถานะ และรายงาน |
| ผู้ประเมิน | อาจารย์ที่เลือกผู้สมัคร ดูข้อมูล ให้คะแนน และส่งผลประเมินของตน |
| แบบประเมินฉบับร่าง | ผลประเมินที่ผู้ประเมินบันทึกไว้และยังแก้ไขได้ |
| ส่งผลประเมิน | การยืนยันผลให้ระบบนำไปคำนวณ |
| ปิดรอบ | การยืนยันว่ากระบวนการประเมินในรอบนั้นสิ้นสุดแล้ว |
| เปิดผลให้แก้ไข | การอนุมัติให้แก้ผลที่เคยส่งแล้ว โดยยังเก็บผลเดิมไว้ |
| การตรวจสอบย้อนหลัง | การดูว่าใครทำอะไรและเมื่อใด |
| ข้อมูลส่วนบุคคล | ข้อมูลของผู้สมัครที่ต้องจำกัดสิทธิ์การเข้าถึง |
