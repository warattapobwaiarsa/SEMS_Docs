## 2. การทำความสะอาดและปรับโครงสร้างจากไฟล์ต้นฉบับ

1. ในไฟล์ Criteria มีเกณฑ์ที่ให้คะแนนจริง 10 เกณฑ์ รวมคะแนนเต็ม 100 คะแนน
2. หัวข้อ “ค่าใช้จ่ายประจำวัน” ปรากฏซ้ำ 2 ครั้ง จึงปรับชื่อหัวข้อที่สองเป็น **“ระดับค่าใช้จ่ายประจำวันต่อเดือน”** เพื่อไม่ให้ชนกันในระบบ
3. เลขลำดับในไฟล์มีเลข 10 ซ้ำสำหรับ “ส่วนร่วมกับคณะหรือมหาวิทยาลัย” และ “การรับทุนต่อเนื่อง” ระบบจึงแยกเป็น:
   - `CRT-10` เกณฑ์ที่มีผลต่อคะแนน
   - `DEC-01` ข้อเสนอการรับทุนต่อเนื่องที่ไม่มีผลต่อคะแนน
4. หัวข้อดุลพินิจในชีต Assessment ระบุว่าสามารถกำหนดคะแนนอื่นได้ จึงรองรับคะแนนกรอกเอง 0–10 โดยต้องระบุเหตุผล
5. หัวข้อมูลค่าทุนระบุว่าสามารถกำหนดค่าอื่นได้ จึงรองรับจำนวนเงินแบบกำหนดเองโดยต้องระบุเหตุผลและไม่เกินเพดานของรอบทุน
6. เครื่องหมาย `-` ในไฟล์ไม่ควรถูกเก็บเป็นคะแนน ระบบต้องใช้ `NULL/ยังไม่เลือก` สำหรับข้อมูลที่ยังไม่กรอก และใช้ตัวเลือกคะแนน 0 ที่มีความหมายชัดเจนเมื่อเป็นคำตอบจริง
7. สำหรับ `CRT-10` ไฟล์ไม่มีตัวเลือกคะแนน 0 ที่เป็นข้อความ จึงเพิ่ม “ไม่มีส่วนร่วมตามเกณฑ์” = 0 คะแนน แทนการใช้ `-`
8. “มูลค่าทุนที่สมควรได้รับ” และ “ความคิดเห็นเพิ่มเติม” เป็นข้อมูลประกอบ ไม่รวมในคะแนนเต็ม 100

## 5. สูตรคำนวณคะแนน

### 5.1 คะแนนรวมรายผู้ประเมิน

```text
evaluator_total = SUM(score(CRT-01) ... score(CRT-10))
```

เงื่อนไข:

- ทุกเกณฑ์ `CRT-01` ถึง `CRT-10` ต้องมีคำตอบก่อน Submit
- คะแนนต้องมาจาก Option Code ที่อยู่ใน Criteria Version ของ Evaluation เท่านั้น
- คะแนนรวมต้องอยู่ระหว่าง 5–100 ตามชุดตัวเลือกปัจจุบัน
- ค่า `weight_percent` เป็นข้อมูลอธิบายน้ำหนัก ไม่ต้องนำไปคูณซ้ำ เพราะคะแนนในตัวเลือกถูกถ่วงน้ำหนักไว้แล้ว
- ตัวอย่างจากชีต Assessment ในไฟล์: `5+5+10+20+10+5+5+5+10+0 = 75`

### 5.2 คะแนนสรุปของผู้สมัคร

```text
eligible = Evaluation ที่ status = SUBMITTED
           และไม่ถูกยกเลิก
           และมาจาก evaluator_id ที่ไม่ซ้ำกัน

ถ้า count(eligible) < 2:
    summary_score = NULL
ถ้า count(eligible) = 2 หรือ 3:
    raw_summary = SUM(evaluator_total) / count(eligible)
    summary_score = ROUND_HALF_UP(raw_summary, 2)
```

ตัวอย่าง:

| คะแนนผู้ประเมิน | จำนวน | ผลสรุป |
|---|---:|---:|
| 75, 80 | 2 | 77.50 |
| 75, 80, 90 | 3 | 81.67 |
| 75 และมีอีก 1 รายการเป็น Draft | 1 Submitted | ไม่มีคะแนนสรุป |

### 5.3 หลักการปัดเศษ

- ใช้ทศนิยม 2 ตำแหน่ง
- ใช้กฎ `Half Up`
- ปัดเฉพาะ `summary_score` ของผู้สมัคร
- ไม่ปัดคะแนนรายเกณฑ์ เพราะเป็นจำนวนเต็ม
- ไม่ปัด `evaluator_total`
- Backend ต้องใช้ Decimal/Numeric ไม่ใช้ Binary Floating Point เพื่อป้องกันความคลาดเคลื่อน

## 6. กฎความคิดเห็น

ความคิดเห็นเพิ่มเติมโดยรวมเป็นข้อมูลไม่บังคับ แต่ระบบบังคับระบุเหตุผลที่ไม่ว่างเมื่อ:

1. เลือก `CRT-04 / USE-OTHER-NECESSARY`
2. เลือก `CRT-09 / JUDGMENT-URGENT`
3. เลือก `CRT-09 / JUDGMENT-OTHER`
4. เลือก `CRT-09 / JUDGMENT-CUSTOM` และกรอกคะแนนเอง

แนะนำให้เก็บความคิดเห็นแบบรายเกณฑ์ (`criterion_comment`) แยกจากความคิดเห็นรวม (`overall_comment`) เพื่อให้ตรวจสอบย้อนหลังได้ชัดเจน

## 7. ข้อมูลประกอบที่ไม่คิดคะแนน

| Field Code | ชื่อ | Required | รูปแบบ | กฎ |
|---|---|---|---|---|
| `DEC-01` | การรับทุนต่อเนื่อง | ใช่ | Boolean/Single Select | เลือก “สมควรได้รับทุนต่อเนื่อง 2 ภาคการศึกษา” หรือ “ไม่เสนอให้รับทุนต่อเนื่อง” |

| `CMT-01` | ความคิดเห็นเพิ่มเติม | ไม่ | Textarea | ไม่เกิน 2,000 ตัวอักษร; อาจถูกบังคับจากกฎแบบมีเงื่อนไขในข้อ 6 |

## 8. Versioning และการล็อกเกณฑ์

### 8.1 สถานะชุดเกณฑ์

```text
DRAFT -> ACTIVE -> RETIRED
```

- `DRAFT`: แก้ไขได้ และยังไม่ใช้สร้าง Evaluation
- `ACTIVE`: ใช้งานกับรอบทุนที่กำหนด
- `RETIRED`: ไม่สร้าง Evaluation ใหม่ แต่ข้อมูลเดิมยังอ่านและรายงานได้

### 8.2 จุดที่ล็อก

เมื่อมี Evaluation ที่ยังไม่ถูกยกเลิกอย่างน้อย 1 รายการ ไม่ว่าจะเป็น `DRAFT` หรือ `SUBMITTED` ให้ล็อก Criteria Version นั้นทันที

ห้ามแก้ไขข้อมูลที่มีผลต่อการตีความหรือคะแนน ได้แก่:

- ชื่อและคำอธิบายเกณฑ์
- คะแนนต่ำสุด/คะแนนเต็ม
- น้ำหนัก
- ตัวเลือกและคะแนนของตัวเลือก
- ลำดับแสดงผล
- Required Flag
- สูตรคำนวณและกฎปัดเศษ

การเปลี่ยนแปลงต้องสร้าง Criteria Version ใหม่ และ Evaluation ทุกรายการต้องเก็บ `criteria_version_id` หรือ Snapshot ของชุดเกณฑ์ที่ใช้

### 8.3 การเปลี่ยนเวอร์ชันในรอบทุนเดิม

หลังเริ่มมี Evaluation แล้ว ห้ามเปลี่ยน Criteria Version ของรอบทุนโดยตรง เพื่อไม่ให้ผู้ประเมินแต่ละคนใช้เกณฑ์คนละชุด หากจำเป็นจริง ต้องผ่านกระบวนการอนุมัติ ยกเลิก Evaluation เดิมทั้งหมด และเริ่มการประเมินใหม่

## 9. Validation และ Error Code

| Error Code | เงื่อนไข |
|---|---|
| `CRITERIA_SET_INCOMPLETE` | ชุดเกณฑ์มีข้อมูลไม่ครบ ผลรวมน้ำหนักไม่ใช่ 100% หรือคะแนนเต็มรวมไม่ใช่ 100 |
| `SCORE_REQUIRED` | มีเกณฑ์บังคับที่ยังไม่เลือกคำตอบ |
| `INVALID_SCORE_OPTION` | Option Code ไม่อยู่ใน Criteria Version ของ Evaluation |
| `INVALID_MANUAL_SCORE` | คะแนนกรอกเองไม่ใช่จำนวนเต็ม 0–10 หรือไม่มีเหตุผลประกอบ |
| `SCORE_OUT_OF_RANGE` | คะแนนต่ำกว่าค่าต่ำสุดหรือสูงกว่าคะแนนเต็ม |
| `EVALUATION_INCOMPLETE` | เลือกตัวเลือกที่ต้องมีเหตุผล แต่ไม่มีความคิดเห็นหรือสั้นกว่าเกณฑ์ |
| `CRITERIA_VERSION_LOCKED` | พยายามแก้ไขเกณฑ์ที่มี Evaluation แล้ว |
| `CRITERIA_VERSION_MISMATCH` | Evaluation ส่งคะแนนด้วย Criteria Version ที่ไม่ตรงกับตอนสร้างรายการ |
| `INSUFFICIENT_SUBMITTED_EVALUATIONS` | พยายามสร้างผลสรุปเมื่อ Submitted น้อยกว่า 2 คน |
| `DUPLICATE_EVALUATOR` | ผู้ประเมินคนเดิมมี Evaluation ซ้ำสำหรับผู้สมัครและรอบทุนเดียวกัน |
| `EVALUATOR_LIMIT_EXCEEDED` | จำนวน Evaluation ที่ยังไม่ถูกยกเลิกเกิน 3 รายการ |
| `ROUND_NOT_OPEN` | พยายามสร้างหรือ Submit Evaluation เมื่อรอบทุนไม่ Open |
| `INVALID_RECOMMENDED_AMOUNT` | จำนวนเงินทุนกำหนดเองไม่เป็นจำนวนเต็มบวก เกินเพดานรอบทุน หรือไม่มีเหตุผล |

## 12. ประเด็นที่ต้องได้รับการอนุมัติก่อนใช้งานจริง

ค่าต่อไปนี้เป็นข้อเสนอแนะที่เติมให้ระบบมีข้อกำหนดครบถ้วน และต้องให้เจ้าหน้าที่งานทุนยืนยัน:

1. ใช้ค่าเฉลี่ยเลขคณิตของผู้ประเมิน 2–3 คน
2. ปัด 2 ตำแหน่งแบบ Half Up เฉพาะคะแนนสรุปสุดท้าย
3. ความคิดเห็นรวมไม่บังคับ แต่บังคับแบบมีเงื่อนไขตามข้อ 6
4. อนุญาตคะแนนดุลพินิจแบบกำหนดเองเป็นจำนวนเต็ม 0–10 และต้องมีเหตุผล
5. อนุญาตจำนวนทุนแบบกำหนดเอง ภายใต้เพดานของรอบทุน และต้องมีเหตุผล
6. ให้เครื่องหมาย `-` หมายถึง “ยังไม่เลือก” ไม่ใช่คะแนน
7. เพิ่มตัวเลือก `CRT-10` “ไม่มีส่วนร่วมตามเกณฑ์” = 0 คะแนน
8. ล็อกเกณฑ์ตั้งแต่มี Evaluation รายการแรกทั้ง Draft และ Submitted
9. เกณฑ์ `CRT-08` ให้ระบบคำนวณจาก GPA อัตโนมัติ หรือให้ผู้ประเมินเลือกโดยระบบตรวจสอบความสอดคล้อง
